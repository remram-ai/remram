# Remram contributor and agent guidance

- Remram remains the landing page for the memory-enhanced OpenClaw experiment and retained projects. Read README.md and docs/overview/repositories.md first.
- Current scope is recorded in docs/overview/2026-10-04-repository-scope.md. Remram, .github, Moltbox Gateway/Services/Runtime, Remram Skills, and Forge remain active.
- Remram Cortex, ElderClaw, and Remram App are retired destinations. Preserve historical source links; do not direct new implementation work into those repositories.
- Memory, retrieval, reflection, and reusable workflow ideas may remain part of the experiment. Historical Cortex proposals do not make a specific memory implementation or database mandatory.
- Livonne commercial/product strategy, care/family/community requirements, hardware engineering, partner records, pricing, and narratives belong in the Livonne organization.
- Keep the existing public/private visibility of every repository. Do not publish private overlays, customer/household context, employer-specific architecture mappings, credentials, or commercial records into public repositories.
- Keep implementation and operator procedures in the owning project. Gateway owns appliance CLI and recovery; Services owns baselines; Runtime owns final deployable artifacts; Skills owns portable packages; Forge owns its separate workflow experiment.
- A README cleanup does not authorize appliance deployment, host changes, repository transfer, visibility changes, domain changes, or website cutover.
- Distinguish proposals, historical claims, implementation, and verified behavior. Use current project sources before historical summaries.
- Preserve historical evidence and Git history unless the user explicitly directs otherwise. Repair changed links and indexes.
- The existing SublimeDelusion/livonne repository must remain available while it serves the website. Archiving it requires confirmed hosting cutover.
